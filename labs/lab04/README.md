# Лабораторна робота №4

## 1. Опис роботи

Розроблено консольну програму для отримання інформації про вразливості з National Vulnerability Database (NVD) за ідентифікатором CVE.

Програма отримує дані через NVD API або читає локальний JSON-файл, перевіряє структуру відповіді, аналізує оцінку CVSS та формує JSON-звіт.

## 2. Індивідуальне завдання

Для варіанта 3 використовується правило:

- Поріг оцінки CVSS: **7.0**.
- Поле: `privilegesRequired`.
- Очікуване значення: `NONE`.

Рішення `review` формується, якщо оцінка CVSS не менша за 7.0 та значення `privilegesRequired` дорівнює `NONE`.

В іншому випадку формується рішення `other`. Якщо даних недостатньо для перевірки, повертається `insufficient_data`.

Також передбачені результати:

- `not_found` — вразливість не знайдена;
- `rejected` — вразливість має статус Rejected;
- `insufficient_data` — недостатньо даних для аналізу.

## 3. Структура проєкту

- `api_client.py` — формування HTTP-заголовків та отримання відповіді від NVD API.
- `analysis.py` — перевірка структури JSON, вибір оцінки CVSS та застосування правила варіанта.
- `main.py` — обробка аргументів командного рядка, читання файлів та формування звіту.
- `data/nvd_sample.json` — синтетичні дані для локального тестування.
- `tests/` — автоматизовані тести.
- `README.md` — інструкція з використання програми.

## 5. Запуск програми

### Локальний режим

Запуск із використанням синтетичного JSON-файлу:

```bash
python -m labs.lab04.main --cve CVE-2099-10001 --input labs/lab04/data/nvd_sample.json
```

У цьому режимі програма читає дані з локального файлу та не виконує HTTP-запит до NVD API.

### Режим NVD API

Запуск із отриманням даних через NVD API:

```bash
python -m labs.lab04.main --cve CVE-2021-44228
```

За потреби API-ключ можна передати через змінну середовища `NVD_API_KEY`. Ключ не потрібно записувати безпосередньо в код або URL.

Команда запуску:

Отримані результати:

## 6. Формат результату

Програма формує JSON-звіт, який містить:

- `cve_id` — ідентифікатор вразливості;
- `variant` — номер варіанта;
- `description` — опис вразливості;
- `vuln_status` — статус вразливості;
- `cvss_version` — версія CVSS;
- `score` — базова оцінка;
- `score_source` — джерело оцінки;
- `vector` — вектор CVSS;
- `rule` — правило перевірки;
- `observed` — фактичне значення поля;
- `decision` — результат аналізу.

Результат виводиться у форматі JSON. У разі помилок повідомлення виводяться окремо в потік stderr.

## 7. Автоматизоване тестування

Для запуску тестів:

```bash

```

Тести перевіряють:

- правильність застосування правила варіанта;
- граничні значення оцінки CVSS;
- відсутність та некоректність даних;
- формування HTTP-заголовків;
- успішні HTTP-відповіді та мережеві помилки;
- роботу командного інтерфейсу;
- читання локальних JSON-файлів.
